Build 循环

FDMET.build() 中每个 ligand 现在在一次迭代中完成：

  1. self._make_fragment_mol(lig_atoms, ...) — 显式构建 fragment 分子
  2. run_fragment_scf(frag_mol, imp_idx, ...) — 运行 SCF，返回 mf
  3. bath_from_ligand_density(dm, imp_idx, lig_idx, ...) — 提取 bath/fo 轨道
  4. fragment_orbitals_to_parent_orbitals(...) — 映射到母体基底

run_fragment_scf (frag_mol, fragment_imp_idx, fragment_scf, fragment_scf_verbose, **kwargs)

代码改动

1. rdiis.py — 新增 RDIIS.setup classmethod（+26 行）

将 options dict 消费（pop diis、rdiis_* 键）、RDIIS 实例创建、可选属性（ent_conv_tol、space）设置集中到一个工厂方法。职责单一：只返回 RDIIS 对象，不做 mf.diis = 挂载。

2. fragment.py — FDMET._make_fragment_mol（新增类方法，+5 行）

薄封装模块级 _make_fragment_mol，内部自动使用 self.mol 和 self._imp_atoms。调用方不再需要传递母体分子和杂质原子参数。

3. fragment.py — run_fragment_scf 签名精简

旧签名(mol, impurity_atoms, ligand_atoms, charge, fragment_scf, fragment_scf_verbose, **kwargs)
新签名(frag_mol, fragment_imp_idx, fragment_scf, fragment_scf_verbose, **kwargs)

变更：不再内部调用 _make_fragment_mol；不再接收 fragment_to_parent_idx 和 fragment_lig_idx（与 SCF 无关）；不再返回 LigandReference，只返回 mf。LigandReference 由 build() 自行组装。

4. fragment.py — FDMET.build() 合并循环

原为两个独立循环（先跑所有 fragment SCF，再提取所有 bath），现合并为单一循环。每个 ligand 的四个子步骤（build mol → SCF → bath → map）按顺序执行，局部变量 to_parent、imp_idx、lig_idx 直接用于 bath 提取，无需通过 LigandReference 间接引用。

5. fragment.py — RDIIS 调用方简化

两处 RDIIS 设置从 ~22/25 行缩减为 ~5/6 行，重复的 options pop 和属性设置逻辑移入 RDIIS.setup。

设计选择 / 当前假设

  • index 解析（_resolve_local_ao_indices 和 _resolve_impurity_embedded_indices）留在调用方而非 RDIIS.setup 内部，因为两个场景使用的基底和解析函数不同。
  • _make_fragment_mol 模块级函数保留，类方法仅作为薄封装。
  • run_fragment_scf 中的 max_memory 默认值从 mol.max_memory 改为 frag_mol.max_memory（两者等值，因为 _make_fragment_mol 已将母体的 max_memory 传递给 fragment 分子）。
  • 删除了 spin = kwargs.pop('spin', None)（已移至 _make_fragment_mol 外部调用处）。
  • RDIIS 默认值（rdiis_prop='dS'、power=0.2 等）与之前完全一致。
